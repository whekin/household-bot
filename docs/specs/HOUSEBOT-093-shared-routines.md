# HOUSEBOT-093 — Регулярные дела

## Summary

Настраиваемые общие списки дел: одна карточка дня в Telegram, те же отметки
в личке и настройка через мини-приложение. Первый сценарий — уход за котятами,
но в коде нет названий животных, обязательных задач или медицинских расписаний.
Основной язык дома и нового сценария — русский; существующие RU/EN настройки сохраняются.

## Goals

- Любой активный участник дома отмечает выполнение и отменяет отметку.
- Группа, личка и мини-приложение показывают единое состояние.
- Настройка занимает несколько минут, ежедневное действие — одно нажатие.
- Расписание можно менять и приостанавливать по мере изменения потребностей.

## Non-goals

В первой версии нет баллов, серий, рейтингов, ротаций, зависимостей, вложенных задач,
LLM-планирования, медицинских рекомендаций, вложений и произвольных cron/RRULE.
Интервалы от последнего выполнения и индивидуальные профили животных отложены.
Расходы остаются в существующем учёте покупок.

## UX и границы первой версии

### Навигация и создание

В «Настройках» — «Регулярные дела». На главной — компактная ссылка «Дела на сегодня»
для быстрого перехода; количество выполненных видно на карточках внутри раздела. Не добавлять отдельную постоянную вкладку до проверки сценария.
Участники видят дела и свои уведомления; администратор управляет общим расписанием
и групповым размещением (исходное продуктовое допущение).

Редактор — отдельный экран с возвратом, а не цепочка вложенных модальных окон:

1. Название списка (например, «Уход за котятами»); эмодзи можно включить в название.
2. Список задач, кнопка «Добавить дело». Новая строка требует только название.
3. Для каждой задачи раскрывается «Расписание»: ежедневно или дни недели;
   «В течение дня» либо конкретные часы. Напоминания выключены по умолчанию.
4. Для задачи с часами — переключатель «Можно взять на себя». Включение не создаёт
   обязательного назначения; рядом пояснение, что любой всё ещё может выполнить дело.
5. «Карточка в группе»: отдельный/известный топик или только личка. Время публикации
   карточки — настройка списка, первоначальное предложение 08:00 по времени дома.
6. Раскрываемый предпросмотр структуры карточки и одна основная кнопка «Создать список» / «Сохранить».

Предпросмотр раскрывается под формой; на широком экране сохраняется компактная ширина.
Использовать существующие React-компоненты, токены темы и формы проекта (в AGENTS.md
упомянут SolidJS, но текущие исходники мини-приложения используют React).
Читаемые подписи, реальные label, фокус и клавиатура, зоны нажатия >=44 px,
ошибки рядом с полем, сохранение введённого при сетевой ошибке, светлая/тёмная темы.
Порядок строк меняется доступными кнопками, drag-and-drop необязателен.
Не выставлять медицинские часы или набор задач автоматически.

### Карточка дня и действия

Одна карточка на список и локальную дату; до 20 отдельных отметок на день,
до 80 символов в названии списка и до 60 в названии задачи. Лимит проверяется
до сохранения расписания, чтобы карточка оставалась компактной.
Каждый временной слот — отдельная отметка, задача без времени — одна отметка.

Кнопка показывает состояние: «☐ 09:00 · Кормление», «✓ 09:00 · Кормление».
Текст карточки показывает исполнителя/время или «Саша занимается».
Повторное нажатие на актуальную выполненную строку отменяет выполнение.

Список из нескольких отметок не превращается в стопку кнопок: по умолчанию карточка
компактная — одна кнопка на актуальный слот («⏰», когда время наступило) и «⋯ Все дела»,
раскрывающая полный список кнопок вместе с «⌃ Свернуть». Актуальный слот — последний
уже наступивший, иначе ближайший будущий; пропущенный ранний слот не отмечается за
пользователя и остаётся доступен в раскрытом виде. Раскрытие хранится у сообщения:
в группе оно общее для всех, в личке — своё. Сверху карточки две строки без относительных
величин: последнее выполнение (время, имя) и ближайший слот. Относительное «через N минут»
переписывало бы сообщение на каждом тике, поэтому используется только абсолютное время.
Цвет кнопок Bot API не поддерживает; состояние передают эмодзи и текст.

Форма создания предлагает «Быстрый старт» — заготовку, которая только заполняет поля
и сразу скрывается. Заготовка не сохраняется сама, не навязывает медицинский режим
и полностью редактируется.
Старая карточка не должна отменять более свежое действие: версия строки входит
в callback, конфликт обновляет карточку и просит повторить действие.

Напоминание: название дела и «Возьму на себя» / «Готово», либо только «Готово»,
если взятие выключено. Универсальные подписи не зависят от пола или типа дела.
После взятия показать имя и кнопку «Освободить» для взявшего; «Готово» доступно всем.
Срок взятия — 30 минут (продуктовое начальное значение, не рекомендация по уходу).
После истечения дело свободно; повторной рассылки автоматически не происходит.

После выполнения обновить дневные карточки и удалить напоминания на всех поверхностях.
После отмены обновить карточки, но не посылать новое уведомление по уже прошедшему слоту.
После смены дня старые карточки только для чтения; незавершённое не переносить как долг.

### Топик

Назначение задаётся для каждого списка, без обязательного топика или названия.
«🐾 Котята» — только пример пользовательской конфигурации. Несколько списков могут
использовать один топик; это не новый `HouseholdTopicRole` и не изменение финансовых привязок.

В настройке «Карточка в группе» три варианта:

- **Создать новый топик**: пользователь задаёт название (первоначально — название
  списка), бот создаёт топик и сразу сохраняет привязку к списку. Проверить Telegram
  admin у инициатора и `can_manage_topics` у бота. До ответа об успехе привязка сохранена.
- **Подключить существующий**: выбрать известный топик или вставить ссылку на сообщение
  из него. Стандартная `/bind` внутри нужного топика остаётся запасным способом. В её меню рядом с ролями доступны кнопки списков этого дома. Отдельную `/routine_bind` и токены для неё не вводить.
- **Не публиковать в группе**: карточка остаётся доступна в личке/мини-приложении.

Сценарий ссылки: поле «Ссылка на сообщение в топике» → распознанное назначение →
«Подключить». Не выполнять привязку автоматически при вставке. Поддержать private
`https://t.me/c/<channel>/<thread>/<message>` и `.../<message>?thread=<thread>`,
а также соответствующие public ссылки с username (resolve через Bot API getChat).
Thread из пути и query должны совпадать, если заданы оба; неоднозначный ввод отклонить.
Пример пользователя содержит channel `2636668636`, thread `136`, message `4223`.

Разбирать URL локально, без HTTP-загрузки сообщения/произвольного URL. Проверять
Telegram hostname, структуру пути, положительные числовые ID и принадлежность
полученного chat текущему дому; публичный username сначала разрешить в стабильный ID.
Ссылка не подтверждает права пользователя, наличие топика или его название:
авторизация обязательна, имя брать только из известных данных. Для неизвестного
топика показывать «Топик по ссылке», не выдумывать название.
Если ссылка не содержит thread, предложить `/bind`; message ID не считать автоматически ID топика.
Не пересылать чужие сообщения и не отправлять пробные сообщения для проверки ссылки.
Неизвестное назначение сохранять как ожидающее проверки доставки: активировать после
успешной публикации штатной карточки; при ошибке показать состояние подключения и
способ исправить ссылку/применить `/bind`, не заявляя об успешной доставке.
Формат: [Telegram message links](https://core.telegram.org/api/links#message-links).

Текущая `/bind` уже проверяет администратора группы и контекст топика; создание
топика уже есть в setup через `createForumTopic`. Переиспользовать этот пользовательский
сценарий и общие проверки, сохраняя отдельное хранение назначения списка.
Меню списков должно быть доступно даже когда все фиксированные роли уже привязаны
(сейчас `/bind` в таком случае завершает обработку раньше показа кнопок).

При перепривязке показать старое и новое назначение и запросить явное сохранение;
это пользовательский шаг настройки, не отдельное согласование разработки.
Старые карточки лишаются кнопок, текущая карточка появляется в новом месте;
будущие напоминания используют актуальное назначение. Сам старый топик не удалять. Привязка сразу публикует карточку текущего дня.
Повтор создания не должен создавать второй топик: сохранять ID результата до дальнейших
шагов; если создание прошло, а привязка упала, повторить привязку к уже созданному.
При неоднозначном сетевом результате не повторять create вслепую: предложить `/bind`.
Без прав создания показать путь ручного создания и `/bind`, без ручного ввода ID.
Ни создание топика, ни сообщение в живую группу не выполняются в ходе разработки.
Ограничения API и первичные источники: [исследование](../research/shared-routines-telegram.md).

### Личка

`/routines` или пункт меню «Дела» показывает списки доступных домов и текущую карточку.
При нескольких домах обязателен выбор дома. Участник может выполнять дела без
подписки на уведомления. Подписка на каждый список включается самим участником
в мини-приложении; если бот ещё не запущен, кнопка «Открыть бота» завершает подключение.
Запрет лички отключает только эту доставку и не ломает группу.

## Domain Rules

- День вычисляется в timezone, унаследованной от дома при создании списка, через Temporal, не по UTC сервера.
  Изменение timezone в финансовых настройках не сдвигает существующие списки.
- Расписание: ISO дни недели 1–7; ноль времён означает одну задачу без срока.
  Время строго HH:mm; дубли дней/времён и невалидные даты отклоняются.
- При переводе часов используется Temporal `compatible`: пропущенное время сдвигается
  вперёд, повторяющееся выбирается раньше; слот остаётся один.
  [Temporal](https://tc39.es/proposal-temporal/docs/zoneddatetime.html#static-methods).
- Сегодняшние строки — снимок названия, параметров и времени. Редактирование действует
  со следующего локального дня; создание нового списка может начать сегодня.
- Пауза немедленно прекращает будущие отправки, сохраняя существующие отметки;
  возобновление не рассылает пропущенные напоминания.
- Действия явные: complete, reopen, claim, release. Не использовать слепой toggle в БД.
- complete доступно любому активному участнику даже при чужом claim.
  reopen доступно любому активному участнику; чужой claim освободить нельзя.
- Claim истекает по абсолютному времени. Истечение само не меняет версию записи;
  следующая команда проверяет актуальность claim с серверным `now`.
- Compare-and-set версии и дедупликация requestId выполняются в одной транзакции.
  Повтор webhook не меняет отметку второй раз. Авторизация предшествует чтению/записи.

## Interfaces and Contracts

- Domain: проверка расписания, раскрытие слотов на дату, переходы состояния.
- Application: создание/редактирование/пауза списков, снимок дня, действие над строкой, личная подписка,
  привязка топика, постановка/выполнение напоминаний, сверка карточек.
- Отдельные ports RoutineRepository и RoutineDelivery; без SDK в domain/application.
- API: list/create/update/pause routine, get day, act on occurrence, update own
  subscription, create/bind/unbind topic destination. Идентичная проверка дома в API и callback.
- Конфигурационный update требует expectedRevision; ошибка конфликта сохраняет
  локальный черновик и предлагает загрузить изменения, а не перезаписывает чужую работу.
- Callback <=64 байт: короткий префикс, ID строки, версия, действие; никакого доверия
  к household/member из payload. Дом выводится из записи, актор — из Telegram auth.

## Data Model Changes

Миграция `0045_nappy_big_bertha.sql` с Drizzle snapshot и checksum manifest добавляет
`household_routines`: text ID, household FK с cascade, JSONB document, updatedAt,
индекс householdId. Небольшой список — единый транзакционный агрегат.

Документ хранит definition, следующую конфигурацию с effectiveDate, revision,
публикацию/назначение, подписки, снимки дней, состояние строк с версиями и исполнителями,
последние requestId, сообщения и их статус доставки, lease, состояние создания топика.
`RoutineRepository.change` использует SELECT FOR UPDATE; callback синхронный, без IO.
Проверка версии, отметка и дедупликация сохраняются одним commit; исключение откатывает всё.
Снимки/сообщения сохраняются 30 дней, requestId — последние 1000; версия дополнительно
защищает от давних повторов даже после вытеснения requestId.

Очередь доставки — состояния сообщений внутри агрегата. Lease на 120 секунд,
обновляемый перед каждым IO; Telegram-вызов ограничен 15 секундами. До send сохраняется
неопределённый результат, затем известный messageId. Прерванный send не повторяется
вслепую; пользователь может явно повторить дневную карточку, проверив отсутствие в чате.

Вместо расширения финансового scheduled_dispatch — отдельная routine sweep внутри
существующего `/jobs/dispatch-due` и self-hosted poller. AWS Pulumi добавляет минутный
`household.routine-tick` с IAM invoke; GCP Terraform — минутный OIDC HTTP job, если
включён Cloud Tasks provider. Без финансового scheduler постоянный сервер использует
собственный 30-секундный poller. Новых cloud secrets нет.

## Security and Privacy

Только active member может читать/отмечать, admin — менять общий список/назначение.
Личная подписка только своя. Привязка только к чату своего дома, с проверкой администратора Telegram-группы. Проверять membership
и в личке, и на пересланных/старых callback. Экранировать названия для Telegram HTML.
В callback нет текста задач и личных данных; в логах нет Telegram initData/токенов.

## Edge Cases and Failure Modes

Сначала сохранить состояние в БД и outbox, затем Telegram. Ошибка редактирования
не откатывает выполнение. Сериализовать обновления по карточке и читать свежую версию
перед отправкой, иначе медленный старый edit затрёт новый. retry_after — с задержкой;
message not modified — успех; missing message — отвязать и восстановить при следующем
явном открытии, без лавины новых сообщений. Удаление старого напоминания может быть
недоступно: заменить текст на завершённый и убрать кнопки; ошибка не блокирует другие копии.

После простоя создавать только сегодняшний снимок; старые дни и просроченные уведомления
не рассылать. Окно догоняющей доставки — до 15 минут и только для незавершённой строки;
проверять состояние непосредственно перед отправкой. У Telegram sendMessage нет ключа
идемпотентности: ambiguous timeout не позволяет гарантировать exactly-once; хранить
неопределённый результат, не повторять отправку вслепую. Edit/delete повторяемы.

## Observability

События routine.action, routine.delivery_failed, routine.card_refresh_failed,
routine.delivery_unknown, routine.topic_unavailable; routine/household/occurrence IDs,
версия, latency, retry count. Отдельно следить за отставанием outbox и истёкшими lease.

## Test Plan

- Unit: дни/слоты/таймзона/DST, валидация, состояния, чужой claim, истечение,

- Telegram: группа ↔ личка, <64 байт, удаление/редактирование, 403/429/timeout,

- UI: мобильный русский интерфейс, тёмная тема, клавиатура, валидация, отмена,
  offline/retry, несколько домов, устаревшая конфигурация; визуальная проверка.

## Acceptance Criteria

- [x] Администратор создаёт произвольный список без ввода технических идентификаторов.
- [x] Сегодняшняя карточка одна на список/поверхность; все копии сходятся после действия.
- [x] Любой активный участник выполняет/отменяет и в группе, и в личке.
- [x] Расписание/пауза/подписки работают без привязки к уходу за животными.
- [x] Повторные и конкурентные запросы не отменяют/не дублируют работу.
- [x] Напоминание удаляется после выполнения; предусмотрен fallback.
- [x] Создание топика сразу привязывает его; существующий подключается по ссылке, из известных или через `/bind`.
- [x] `/bind` показывает списки даже при заполненных финансовых ролях; перепривязка и
      сбой после создания не дублируют топики или активные карточки.
- [x] Проверены права, восстановление после ошибок, UX и полные quality gates.

## Rollout Plan

Реализация завершена в рабочем дереве; production rollout — после отдельного запроса.
Runbook: [shared-routines](../runbooks/shared-routines.md).

Сначала domain и тесты, затем БД/application, Telegram/scheduler, mini app,
сквозная проверка в тестовом доме. До завершения всей цепочки пользовательского
пункта «Дела» в production нет. Создание живого списка, расписания ухода и отправка
в группу — отдельная настройка пользователем после выкладки. Коммит только по запросу.

## Проверка реализации

Domain/application/Telegram tests; реальный PostgreSQL в отдельном временном контейнере
(миграция с нуля, конкурентные действия, rollback и восстановление очереди).
API+Telegram сквозной тест использует подписанный initData и имитацию Telegram API,
не живую группу. Русский мобильный интерфейс проверен в браузере на ширине 390 px.
При отсутствии дел по расписанию новая автоматическая карточка не отправляется;
если напоминание раньше времени публикации, карточка появляется вместе с ним.
Удалённая дневная карточка восстанавливается только при явном открытии/перепривязке.
