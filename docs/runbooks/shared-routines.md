# Регулярные дела

Spec: [HOUSEBOT-093](../specs/HOUSEBOT-093-shared-routines.md).

## Выкладка

1. Применить стандартные Drizzle migrations, включая `0045_nappy_big_bertha.sql`,
   до запуска новой версии бота. Миграция добавляет одну таблицу; старый бот её не использует.
2. Собрать и выложить bot + mini app. Self-hosted Compose уже запускает scheduler;
   `/jobs/dispatch-due` обслуживает и регулярные дела. Poll interval — не более минуты.
3. Для AWS применить обновлённый Pulumi stack: минутный `household.routine-tick`
   вызывает Lambda через существующую scheduler IAM role. Для GCP применить обновлённый
   Terraform: минутный OIDC job добавляется при настроенном Cloud Tasks provider.
   Нельзя полагаться на таймер внутри замороженного serverless instance.
4. В мини-приложении: «Настройки → Регулярные дела → Создать список».
   Задать пользовательские задачи и часы; названия/медицинский режим не предзаполняются.
   «Быстрый старт» только заполняет форму заготовкой; любое поле можно изменить до
   сохранения, и заготовка не является рекомендацией по уходу.
5. «Топик»: создать и сразу подключить, выбрать известный, вставить ссылку или
   отправить `/bind` внутри нужного топика. Требуются права администратора дома и группы;
   для автоматического создания бот должен иметь `can_manage_topics`.
6. Каждый участник открывает бота через «Открыть дела в боте» и включает собственную
   подписку. `/routines` и кнопка «Дела» в личном меню доступны без подписки.

Ссылка должна содержать thread: `t.me/c/<channel>/<thread>/<message>` либо
`t.me/c/<channel>/<message>?thread=<thread>`. Публичные аналоги поддерживаются.
Ссылки на чужой дом и ссылки без thread отклоняются; содержимое сообщения не скачивается.

## Поведение

- Одна дневная карточка списка в каждом месте, единые отметки и исполнители.
- В карточке с несколькими отметками кнопок две: актуальный слот и «⋯ Все дела».
  Раскрытие хранится у сообщения, поэтому в группе его видят все; «⌃ Свернуть» возвращает
  компактный вид. Отмена выполнения доступна в раскрытом списке и в мини-приложении.
- Текст карточки показывает последнее выполнение и ближайший слот абсолютным временем:
  относительное «N минут назад» переписывало бы сообщение каждую минуту.
- Любой активный участник выполняет и отменяет; чужой активный claim нельзя освободить,
  но можно выполнить задачу. Claim истекает через 30 минут без новой рассылки.
- Изменения задач — с завтрашнего дня. Пауза немедленно прекращает новые напоминания.
- Карточка публикуется в заданное время или с первым более ранним напоминанием;
  если на день нет задач, автоматическая карточка не появляется.
- Отменённое выполнение после срока не создаёт новое напоминание. После простоя
  допускается только 15-минутное окно догоняющей отправки.
- Ошибка Telegram не откатывает отметку. Обновления сходятся при следующем tick.
- Состояние топика в UI различает ожидание, подтверждённую доставку, ошибку и
  неопределённый результат. URL сам по себе не подтверждает наличие топика.

## Восстановление

- **Бот заблокирован в личке:** открыть его, нажать Start, открыть карточку или
  заново включить личную подписку. Групповая доставка при этом продолжает работать.
- **Карточка удалена:** явно открыть её через `/routines`; для группы переподключить
  текущее назначение. Планировщик не создаёт лавину замен.
- **Неопределённый send timeout:** проверить чат. Если дневной карточки нет — нажать
  соответствующую кнопку повторной отправки в mini app. Автоматического повтора нет.
- **Неопределённое создание топика:** проверить группу; подключить существующий по
  ссылке или через `/bind`. Повтор create без проверки заблокирован, чтобы не плодить темы.
- **Устаревшая версия:** обновить карточку/форму; локальный черновик формы сохранён.
- **Удаление напоминания недоступно:** бот пытается отредактировать его и снять кнопки.
  Missing message считается очищенным, 429 использует retry_after, 403 отключает доставку.

Логи: `routine.delivery_failed`, `routine.tick_failed`, `routine.refresh_failed`,
`routine.topic_creation_failed`, `routine.api_failed`. JSONB `messages` содержит
error/retryAt/status; `lease` ограничен по времени. Исправления напрямую в JSON не нужны.

## Локальная проверка

`bun test packages/domain/src/routines.test.ts packages/application/src/routine-service.test.ts
apps/bot/src/routine-delivery.test.ts apps/bot/src/routine-runtime.test.ts`.

Интеграционный тест адаптера использует **только** `ROUTINE_TEST_DATABASE_URL`:
направить переменную на одноразовую базу, применить миграции и выполнить
`bun test packages/adapters-db/src/routine-repository.test.ts`.
Проверяются конкурирующие нажатия, повтор webhook, rollback и durable delivery intent.
API/Telegram E2E эмулирует Telegram; живые сообщения тесты не отправляют.

Стандартные gates: pre-commit lint/format, pre-push migration hygiene/typecheck/test/build.
Для проверки без коммита: `bunx lefthook run pre-push --force`.
Terraform validate и Pulumi typecheck не создают ресурсы. Перед merge обязателен Codex review.

## Откат

Вернуть предыдущую версию приложения; новая таблица может остаться без использования.
Остановить новые routine-tick cloud jobs при откате инфраструктуры. Данные списков
не удалять: это позволяет безопасно повторить выкладку.
