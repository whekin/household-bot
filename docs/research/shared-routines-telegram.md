# Общие домашние дела: Telegram

Проверено 10 сентября 2026 года по официальной документации. Ниже факты платформы и отдельно проектные решения.

## Ограничения платформы

- Inline-кнопки передают `callback_data` размером 1–64 байта. Callback содержит пользователя; необходимо вызывать `answerCallbackQuery`. [Кнопки](https://core.telegram.org/bots/api#inlinekeyboardbutton), [callback](https://core.telegram.org/bots/api#callbackquery).
- Текст и inline-клавиатуру можно редактировать; текст ограничен 4096 символами. [Редактирование](https://core.telegram.org/bots/api#editmessagetext).
- Свои сообщения в группе/личке бот удаляет только моложе 48 часов. [Удаление](https://core.telegram.org/bots/api#deletemessage).
- Создание группового топика требует администратора с `can_manage_topics`. Адрес доставки — `chat_id` + `message_thread_id`. Метода перечисления всех топиков в Bot API нет; идентификатор приходит в сообщениях. [Создание](https://core.telegram.org/bots/api#createforumtopic), [доставка](https://core.telegram.org/bots/api#sendmessage), [сообщение](https://core.telegram.org/bots/api#message).
- Webhook повторяет неуспешную доставку; `update_id` позволяет распознавать повторы. При flood control `retry_after` задаёт задержку. [Webhook](https://core.telegram.org/bots/api#setwebhook), [Update](https://core.telegram.org/bots/api#update), [ошибки](https://core.telegram.org/bots/api#responseparameters).
- Бот не начинает личную переписку самостоятельно: участник должен сначала написать ему. [Введение](https://core.telegram.org/bots#how-are-bots-different-from-users).
- Deep link `https://t.me/<bot>?start=<payload>` передаёт контекст через `/start`; payload ограничен 64 символами. [Deep linking](https://core.telegram.org/bots/features#deep-linking).
- Telegram рекомендует максимум одно сообщение в секунду в чат; для группы указан предел 20 сообщений в минуту. [Лимиты](https://core.telegram.org/bots/faq#my-bot-is-hitting-limits-how-do-i-avoid-this).

## Рекомендации для реализации

Это наши решения, а не требования Telegram:

- Назначение топика настраивается для каждого списка: создать новый и привязать, подключить существующий либо отключить публикацию в группе. Разрешить существующий: список известных топиков плюс привязка командой внутри нужного топика. Не требовать ручного ввода идентификаторов.
- Использовать одну запись выполнения на дело/дату/слот; групповая и личные карточки — её представления. Проверять членство в доме при каждом действии.
- Кнопка хранит компактные идентификатор, действие и версию. Атомарная проверка версии предотвращает случайную отмену при одновременных нажатиях; намеренная отмена доступна на обновлённой карточке.
- Дедупликация входящих событий и очередь обновлений отделяют сохранение выполнения от доставки. Сериализовать обновления каждой карточки; ошибка Telegram не отменяет выполненное дело.
- После выполнения удалить напоминания во всех местах; при невозможности удаления снять кнопки и показать итог. Отсутствующее сообщение считать уже очищенным.
- Личные напоминания включаются участником через «Подключить в личке». Отказ/блокировка отключает доставку этому получателю, сохраняя общую карточку.
- «Беру на себя» — отдельное состояние; «Готово» доступно без предварительного взятия. Время, повторения и подписи задаются пользователями.

## Что уже есть в репозитории

- [Live payment cards](../../apps/bot/src/live-payment-cards.ts) сохраняют адреса карточек
  и редактируют их после изменения данных. Переиспользуем подход, но не финансовые типы:
  для дел нужны версии рендера, очередь повторов и собственный реестр сообщений.
- [Scheduled dispatch port](../../packages/ports/src/scheduled-dispatches.ts) уже отделяет
  отложенную отправку от провайдера. Добавление новых kind требует полного пути
  repository → application → scheduler runner, а не только расширения строкового union.
- [Household configuration](../../packages/ports/src/household-config.ts) содержит членство,
  timezone и фиксированные роли топиков. Назначение списка должно храниться отдельно,
  иначе несколько произвольных списков не впишутся в фиксированные роли.
- [Settings](../../apps/miniapp/src/features/settings/settings-view.tsx) использует React
  и существующие sheet-компоненты; редактор расписания должен использовать ту же тему,
  но отдельный экран для избежания вложенных sheet. Это проектное UX-решение.
- [Temporal](https://tc39.es/proposal-temporal/docs/zoneddatetime.html) уже используется
  в domain и scheduler. Для расписаний выбрана явная политика `compatible` при DST:
  неоднозначное время раньше, пропущенное — сдвиг вперёд.

Подробный UX, допущения и очередность: [HOUSEBOT-093](../specs/HOUSEBOT-093-shared-routines.md).

## Уточнение существующего setup flow

[household-setup.ts](../../apps/bot/src/household-setup.ts) уже реализует `/bind`
с выбором роли и кнопочное создание через `createForumTopic` с последующей привязкой.
Для регулярных дел расширяем этот сценарий выбором списка, без новой команды.
Нынешний ранний выход при заполненных ролях необходимо изменить, иначе новые списки
будут недоступны для подключения. Проверка Telegram group admin сохраняется.

## Привязка по ссылке на сообщение

Официальный формат включает private `t.me/c/<channel>/<thread_id>/<id>` и
`t.me/c/<channel>/<id>?thread=<thread_id>`; public варианты используют username.
[Telegram message links](https://core.telegram.org/api/links#message-links).
Ссылка пользователя разбирается в channel 2636668636, thread 136, message 4223.
Это разбор адреса, не проверка наличия/названия топика. Решение: поле вставки ссылки,
проверка дома/прав, явное «Подключить»; `/bind` — запасной сценарий. Ссылки без thread
не позволяют однозначно вывести топик без сохранённого контекста сообщения.
